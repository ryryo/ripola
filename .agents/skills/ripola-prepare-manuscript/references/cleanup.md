# 読み上げ用コピーを整える

この手順は人が直接使えます。音声生成を始める前に、原本を保持したコピーを用意します。整形によって著者の主張・語彙・語順を変えないことを基本にします。

## 入力と作業先

1. 原稿の形式、文字コード、文字数、章・節・注・図表の位置を確認します。元ファイルのbyte列のSHA-256を記録します。
2. 利用者が指定したGit外のdirectory、またはrepo rootのGit対象外`local-inputs/`へ新しい作業directoryを作ります。本文だけでなく変更記録や読み辞書候補も同じ場所に置きます。既存の出力は上書きしません。
3. 原本を保存したまま、UTF-8のTXT/MDコピーで作業します。文字コードを変換する場合は変換前のhashを保持し、文字化けを確認します。

取り込みの上限は現在100万文字・20MiBです。PDFはテキスト層がある横書き1段が対象で、画像PDFのOCR、縦書き・段組の復元は未対応です。取り込み仕様は[開発資料](../../../../docs/development/import-pipeline.md)、実際の制限は[text-import.ts](../../../../apps/web/src/reader/text-import.ts)で確認できます。抽出に失敗したPDFを空の原稿として先へ進めません。

## 整形の判断

| 対象 | 扱い |
| --- | --- |
| 語や文の途中で切れた改行 | 前後が連続する本文であることを確認して結合する。空行もページ抽出由来の場合があるため、一括置換しない |
| 段落・章・節 | 論理的な区切りを保つ。Markdownの`#`、`##`、`###`を構造に合わせて付ける |
| 文の断片やページ番号に付いた見出し記号 | 周辺の文へ戻す。独立した番号はページ番号か小節番号かを調べる |
| 目次と本文の重複 | 本文の見出しを残す。重複する目次を読み上げ対象から除く場合は除外範囲を記録する |
| OCR誤字・脱字 | 元資料等の根拠があれば訂正する。文脈からの推測だけなら候補と未解決箇所へ残す |
| 旧字・表記ゆれ・歴史的表現 | 誤りと決めつけて現代表記へ統一しない |
| 図表・写真の説明、引用、脚注・参考文献 | 読む目的と本文との関係で扱いを決める。説明を削ると本文が理解できなくなる場合は残す |
| 注番号やMarkdownのescape | 注本文との対応、コードやURLでの意味を確認する。括弧・数字・backslashを一括削除しない |

目次や参考文献を除くかなど、作業に大きく影響する好みが不明な場合は、理由と推奨案を示して確認します。その間も確実な改行修復や構造調査は進められます。判断を待つ箇所を推測で消しません。

## 表示本文と発音

読みにくい固有名詞、数字、略語は、表示する原綴りを残し、必要な読みを別の辞書候補に記録します。読み上げを改善する目的だけで全文を仮名やNFKC表記へ置き換えません。明確なOCR訂正と、TTSに与える読みの指定は別の変更です。

辞書候補には表記、読み、適用箇所、根拠または要確認を記します。人名や地名の読みが不確かな場合は正解として登録せず、試聴で確認する対象へ回します。音声生成の辞書操作は[VOICEVOXの手順](../../ripola-generate-audio/references/voicevox.md)、表示文と発話文の対応は[生成の開発契約](../../../../docs/development/local-generation.md)を参照します。

## 保存前の確認

- 原本との差分を見て、文字や段落が意図せず欠落・重複・移動していないか確認します。
- 各修正を元位置とともに記録し、根拠のない訂正は未解決一覧に残します。元位置は整形後に採番し直さず、原本の座標を保持します。
- 冒頭だけでなく、長文途中の改行、引用、章境界、脚注、末尾を抜き取り確認します。
- Ripolaへの取り込みプレビューで見出し・段落・本文を確認し、[分割手順](splitting.md)へ進みます。

この段階の確認は音声の試聴ではありません。VOICEVOX/Geminiへの合成要求は行いません。
