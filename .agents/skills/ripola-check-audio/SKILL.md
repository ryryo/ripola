# Ripolaの保存音声を検査する

保存済みbook/revisionまたは配布出力を対象に、構造の整合性と音声品質の兆候を分けて確認する。

## 進め方

1. 利用者の保存先、book ID/revision、必要ならchunk ID、症状を特定する。作者のlibraryや特定デモIDへ固定しない。
2. 欠落・順序・時刻・配布ファイルの確認には[構造監査](references/presentation-audit.md)、無音・音割れ・長さや保存結果の参照には[保存音声QA](references/saved-audio.md)を読む。依頼に必要な検査だけを実行する。
3. repo rootの既存`audit:audio` / `inspect:audio`を使う。検査対象が壊れている、またはツール不足で検査できない状態を合格扱いしない。
4. warningと疑わしいchunkを元範囲・時刻・根拠付きで絞り、試聴できた範囲と機械検査だけの範囲を分ける。ASRは明示的な実験時だけ使う。
5. 修正が必要なら、原稿/読み、音声、表示時刻、配信のどこに問題があるかを整理する。検査依頼だけで原稿・cue・音声を変更しない。修正まで依頼されていればその範囲で進める。

`inspect:audio`はQAのsidecar/cacheだけを書く。検査のために生成job、整列job、モデル取得、TTS、有料APIを起動しない。ASR候補を正解や本文へ置き換えず、CTC scoreを発話内容や時刻精度の保証にしない。

## 完了時に伝えること

対象ID/版、実行した検査、構造上の成否、品質warning・判定不能・未検査、試聴結果、次に必要な作業を伝える。終了コード0は音声品質の合格を意味しない。個人の本文・pathを含む検査出力はGit対象外へ置く。
