# 本文負荷による黙読ペース（評価モード）

既定は従来の字数比例です。「黙読ペースを比較」または表示設定の「読むリズム」で「本文の負荷に配分（評価）」を選びます。既存の100〜3,000字/分と句読点休止を使い、別の速度設定は追加しません。切替時は現在位置で停止します。同じ本文・CPM・休止設定で先頭から比較してください。

## 入力と境界

[pace.ts](../../apps/web/src/reader/pace.ts)は通常本文の`ReadingUnit.text`、grapheme速度字数、CPM、休止だけを使います。ルビのreading・発話本文・読み辞書・音声・providerは入力にしません。表示本文、source span、unit ID、分割、表示グループを変更しません。コード・表は時間0で手動確認のままです。

音声は引き続きmedia時計を使います。`AudioReader.tsx`、音声timeline、合成・cacheキー、保存WAV/MP3/旧AAC、公開静的再生の契約を変更しません。`playback.durationMs`の単位ごとの従来契約も維持します。黙読Controllerだけが全文の配分表を参照します。

## 説明可能な仮の重み

空白・Unicode Punctuationを除くgrapheme数を`g`とし、数字・Latin文字を含むgrapheme数を`n`・`l`、Unicode開閉括弧数を`b`とします。結合文字・異体字・絵文字をUTF-16長で数えません。全角数字・全角英字もUnicode分類で扱います。

```text
multiplier = 1 + 0.30 × n / max(1,g)
               + 0.20 × l / max(1,g)
               + 0.15 × min(2,b)
               + 0.30 × clamp((g - 12) / 12, 0, 1)
weight     = g × multiplier
```

数字と英字は割合、括弧は2個まで、長句は12〜24字で漸増させ、倍率の増加を有限に抑えます。意味・専門性・読者の慣れを判定するものではありません。これらの係数は説明可能な仮説で、実測済みの理解度向上や最適ペースとは表現しません。数字の発音展開や英語のWPMにも換算しません。

## 正規化と下限

従来の全文予算を維持します。休止は読点100ms、文末250ms、段落400ms、見出し600msの分類を一回加えます。

```text
raw_i       = 60,000 × g_i / CPM
displayBudget = Σ max(100, raw_i)
display_i   = max(100, scale × weight_i)
Σ display_i = displayBudget
duration_i  = display_i + pause_i
```

小さいweightを順に100msへ固定し、その分の予算とweightを除いて残りを比例配分します。

| 配分案 | 判断と理由 |
| --- | --- |
| 単位ごとの時間へ倍率を掛ける | 不採用。全文の総時間とCPM意図が変わる。 |
| 下限なしで全文を正規化する | 不採用。100msを下回る単位が出る。 |
| 休止をweightへ混ぜる | 不採用。既存の休止選択を変えてしまう。 |
| 全文予算を下限付きで配分する | 採用。従来の全文予算と固定休止を保つ。 |

全単位が下限なら負荷による差は出ません。従来の単位別下限による`Σ max(100,raw_i) - Σ raw_i`の追加を両モードで保ち、UIへ表示します。全文の生の文字時間が「本文単位数×100ms」より小さいCPMは、全単位への最低配分自体が実行不可能と区別して表示します。全文の生の予算が下限の総和以上でも、短い単位の従来下限による追加は比較のため維持します。評価モードによる追加の総時間超過はありません。下限を保ったうえで残りがあるときだけ相対配分できます。括弧だけの単位など速度字数0の本文も100msを確保します。浮動小数点の端数は最大配分へ補正し、msへの整数丸めは行いません。

予定総時間には両モード共通の従来予算を使います。配分表の合計に残る微小な浮動小数点誤差で、比較欄の小数表示が揺れることを避けます。配分表の時間自体は整数msへ丸めません。

例えば休止なし・600字/分で同じ4字の「日本語文」と「1234」は、従来400msずつ、評価では約347.83msと452.17msです。合計800msは変わりません。これは算術例で、読みやすさや理解度の測定結果ではありません。

## 操作と設定保存

Controllerはloadと時間設定の変更時に配分表・累積時間を作ります。単位送り、seek、再開、残り時間、進捗はその表と単一monotonic clockを使います。pauseは単位内の経過時間を保持し、resumeは残りを表示します。古いcallbackはseek/load/disposeで無効化します。遅延してもフレーズを飛ばしません。

途中の速度・休止・ペース変更では表示中フレーズの時間と現在進捗割合を保ち、後続に新しい配分を適用します。seekは新しい全文表の移動先へ戻します。したがって途中変更直後の実際の残り時間は、先頭から読み直す全文予算と異なる場合があります。既存の進捗epoch契約を継続します。表示のfont/ruby/まとめ設定は時間配分を変えません。

任意の`ReaderSettings.readingPace`を既存のlocalStorageと明示保存IndexedDBに追加します。未保存・旧値・不明なlocalStorage値は`legacy`へ戻ります。不正なIndexedDB値は既存の保存データ検査で拒否します。既存のsettingsVersion 2、schemaVersion 1、保存CPMと音声倍速を維持します。表示リセットでも選んだ黙読ペースを保持します。音声画面にはこの選択UIを出しません。

## 背景資料と測定の範囲

[背景記事](https://nyosegawa.com/posts/speech-cpp/)と[speech.cpp一次資料](https://github.com/nyosegawa/speech.cpp)を確認しています。本モードは音声処理の時間と独立したRipolaの黙読用配分で、係数は音声モデルから得た実測値ではありません。TTS/ASR速度、理解度、実機スマホの評価はこの変更では測定しません。

2026-10-12に[Irodori文書](https://github.com/nyosegawa/speech.cpp/blob/main/docs/models/irodori-tts.md)と[GGUFモデルカード](https://huggingface.co/sakasegawa/Irodori-TTS-v4.1-Small-MF-GGUF)を確認しました。MF F16ファイルは約1.92GBです。本機能はモデルを使わず、取得・実合成を行いません。記事・上流の別機器の速度をこのPCの性能保証に読み替えません。speech.cppはMIT、モデルカードはIrodori/codecのMITとcodec元モデルのApache-2.0、および本人同意のない声の模倣や誤情報目的での使用禁止を説明しています。モデルや第三者音声を本PRに同梱しません。

## 検証対象

画面・検査条件は[検証記録](reading-pace-validation.md)を参照してください。

- 同字数の数字・英字・括弧への相対配分、長句の字あたり配分、従来と同じ全文予算、休止独立、100ms下限と実行不可能なCPM。
- Unicode結合文字・絵文字・全角英数字、長い単位・多数単位、ルビreadingに依存しないこと。
- fake monotonic clockによるpause/resume、seek、設定変更、末尾、静的ブロック、遅延・古いcallback、従来playback回帰。
- 保存と旧値互換、PC/狭幅で選択・比較・停止・保存復元、音声時計への非干渉、`pnpm check`と関連ブラウザ検査。
