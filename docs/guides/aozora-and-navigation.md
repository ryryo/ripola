# 青空文庫の全文・文移動・音声の読み

トップの「吾輩は猫であるを読む（全文・全11章）」で、夏目漱石の作品全体を端末内で準備します。これは黙読用の全文です。公開音声デモの「吾輩は猫である・冒頭約1分（ずんだもん）」は、トップの「音声付きデモを試す」から直接開く、冒頭13文・通常速度で約61秒の無料VOICEVOX音声です。既定の2.5倍では約25秒で、デモからはトップへ戻れます。旧冒頭3文の保存物も保持しています。全編の音声を生成したものではありません。

文一覧は既定で閉じています。「文一覧を開く」で停止して開き、再生すると閉じます。PCの右一覧とスマホのパネルは同じ契約です。現在文を色で示し、前後の文、文番号、章へ移動できます。移動時には停止します。長文の一覧はスクロール位置の周辺だけを描画します。スマホ幅では「文一覧を開く」からパネルを開き、文選択後に読書画面へ戻ります。

## ルビと元資料を保つ

青空文庫のHTMLファイルはShift_JIS／UTF-8を判定し、`parse5@8.0.0`でデータとして解析します。HTMLをDOMへ挿入せず、script、DTD、外部画像を実行・取得しません。`main_text`だけを再生本文とし、見出しを章として保持します。

親文字を本文、`rt`をルビとして分離し、UTF-16で元のHTML文字位置を保存します。読み上げには読みと判定できたルビを使います。「ママ」などの注記と、読みと確定できないルビは画面表示だけに使い、親文字を読ませます。`rp`の括弧、書誌、入力者注は発話本文へ混ぜません。

外字画像は説明・画像参照文字列・元位置を保持し、本文では〓で表示します。画像を取得したり、alt説明を発音として代用したりしません。外字に読みルビがあれば、その読みを使えます。全文の書誌、入力者・校正者、表記の注意、外字と注は「作品の出典・ルビ・外字・入力者注」で確認できます。

[原HTML](https://www.aozora.gr.jp/cards/000148/files/789_14547.html)の固定入力は1,219,970 byte、SHA-256 `6d6f183529b1c4d87941e5d8c44a8d012beeedaba1cbe0fb5e586fcf38bd46df`です。11章、ルビ9,214件、外字画像36件、入力者注6件を含みます。[準備スクリプト](../../scripts/prepare-aozora-sample.ts)はhashと件数が変わった入力を拒否し、全章の静的JSONを作ります。JSONは全文の原HTMLを不活性なデータとして保持します。実行中に青空文庫を任意URLの代理取得先として使いません。

底本は『夏目漱石全集1』ちくま文庫、筑摩書房、1987年9月29日第1刷。親本は1971年4月5日初版の筑摩全集類聚版です。入力は柴田卓治、校正者は原資料に記載された各担当者を保持しています。公開1999年9月17日、修正2018年2月5日の記録を保存します。近代の歴史的な表現も原資料のままです。[図書カード](https://www.aozora.gr.jp/cards/000148/card789.html)、[利用案内](https://www.aozora.gr.jp/guide/kijyunn.html)、[注記仕様](https://www.aozora.gr.jp/annotation/)が出典です。図書カード・書誌データのCC BY 4.0と、本文の著作権状況を同一のライセンスとは扱いません。元の入力・校正・底本の記録を保ちます。

## 速度の初期値

新しく開く黙読は**400文字/分（CPM）**から始めます。保存済みの読書設定はその値を復元します。これは内容理解を保証する速度や、研究で確定した最適値ではありません。

[石森・桐谷（2024）](https://www.jstage.jst.go.jp/article/jssd/71/0/71_46/_article/-char/ja/)は「一節ごと」の日本語RSVPを約240／360／480文字/分で比較し、理解度に有意差を検出せず、通常表示の印象が良かったと報告しています。有意差がないことは同等性の証明ではなく、400そのものは検証条件ではありません。[富松（1999）](https://doi.org/10.15017/4060945)では小型画面の文節表示について選択された読みやすい速度が約362文字/分でした。対象年齢・小型画面・古い条件を踏まえ、400を控えめな設計上の初期値にしています。論文と現実装の単位は[実分割の照合](../research/rsvp-segmentation-check.md)で区別します。

[北名ほか（2025）](https://www.l.u-tokyo.ac.jp/AandC/documents/2025/17.pdf)の音読正答による表示閾値は黙読の理解度CPMと区別します。[小林（2016）](https://www.jstage.jst.go.jp/article/jkg/66/10/66_525/_pdf/-char/ja/)の通常読書500〜600文字/分を、RSVPの最適値として転用していません。アプリは空白・句読点を文字数から除き、句読点休止・最小表示時間も加えるため、論文の文字数と厳密に同じ分母ではありません。WPMやフレーム/分とも異なります。

音声は独立した**2.5倍**から始めます。ユーザー指定の初期値であり、CPMから変換した値ではありません。音声の倍速は`HTMLMediaElement.playbackRate`だけに適用し、合成や保存WAVを変更しません。VOICEVOXの新しい生成はEngineのspeaker／styleメタデータから「ずんだもん／ノーマル」を選びます。style IDは固定しません。保存済みの本の声・生成条件は変更しません。

冒頭音声は「吾輩は猫である。名前はまだ無い。どこで生れたかとんと見当がつかぬ。」だけです。吾輩→わがはい、見当→けんとうを元のルビから用い、「生れた」の表記は保ちます。クレジットは**VOICEVOX:ずんだもん**です。[VOICEVOX利用規約](https://voicevox.hiroshiba.jp/term/)と[ずんだもんの音源条件](https://zunko.jp/con_ongen_kiyaku.html)に従います。声の条件を製品のソースコードLICENSEへ採用するものではありません。

## 保存音声の低信頼部分

従来のCTC単独検証では「一冊の」「ひと」「原文を」が、それぞれ0.204／0.380／0.704で0.75未満でした。元音声・発話原稿の一致と、読みの表記を確認しています。かなの既知原稿とモデルの正書法語彙の相性が影響する可能性がありますが、3件全ての原因を人手の音声境界で確定したものではありません。閾値やCTCスコアは変更しません。

VOICEVOX Engine **0.25.2**では、[上流の音素フレーム処理](https://github.com/VOICEVOX/voicevox_engine/blob/0.25.2/voicevox_engine/tts_pipeline/tts_engine.py)が子音・母音を別々に93.75フレーム/秒へ丸めます。この処理の数値仕様に基づいて発話時刻を得ます。文字数の比率から時刻を作りません。丸めはNumPyのties-to-evenに合わせ、前後無音・句読点の間・speedScaleも区別します。疑問文の末尾音素追加など未対応のqueryには推定時刻を付けません。

新しい合成では、実際に送信したqueryをWAV hash・発話原稿hash・Engine version・style IDに結び付けて非公開保存します。古い音声は同じEngineでqueryを再構成し、WAVのフレーム数一致、全フレーズの音素列一致、2件以上の採用済みCTC cueが対応する音素区間内に入ることを検査します。CTC cueは0.75以上のものだけです。区間包含の判定ではEngine区間の外側へ80 msの余裕を設けます。**CTCとEngineの両端が80 ms以内で一致するという条件ではありません。**無音・形式違い・hash不一致は採用しません。再構成は`audio_query`だけを呼び、合成を再実行しません。

元の自作3文では予測フレーム数206／229／287が各WAVの実長と一致し、各文3件のCTC cueで照合できました。12フレーズ全てに`voicevox-mora`の推定時刻を付けています。9件採用・3件低信頼という元のCTC結果は別の診断として保持します。VOICEVOX方式に架空のCTCスコアを付けず、表示も「合成時に保存」と「再構成による推定」を区別します。旧WAVの画面には元queryとの同一性が未確認であることを表示します。Engineの条件を確認できない場合は採用できるCTC時刻を使い、残りも表示用の推定時計で区切り表示を保ちます。

旧WAVの元queryは保存されていません。今回の条件照合は、そのqueryを厳密に復元したことの証明ではありません。音素列の一致は再構成した全文queryと各フレーズqueryの間で検査しており、元WAVの全音素を認識して一致を確認したという意味でもありません。保存発話原稿からの読み・声・Engine version、完全なモーラ対応、全WAV長、採用済みCTC区間という独立した条件で再構成を絞る方法です。総WAV長が一致するだけで、各音素や低信頼3フレーズの実境界が正確だとは判定できません。

今回の9件のCTC区間では、CTC開始−Engine開始が−36.0〜118.7 ms、CTC終了−Engine終了が−190.7〜−90.7 msでした。CTCの文字の採用区間とEngineの全音素区間は同じ定義の境界ではなく、この差は人手goldに対する誤差ではありません。単体テストでは**長さが同じでも音素が異なるquery、範囲外のCTC時刻、低scoreのCTC、アンカー不足、別Engine、発話hash違い、無音**を拒否することを確認します。実声の人手による音素境界goldは用意できておらず、低信頼3件も含め、時刻誤差のp50／p95／最大値は未測定です。

AAC配布では、この方式も従来どおり元WAVとdecode後PCMの相関による時刻検証を必要とします。query本体・発話原稿・キャッシュ・モデル・個人pathは公開assetに含めません。公開するのは時刻cueと、方式・version・フレーム数・query hash等の限定した検証情報です。Engineの時刻は人手で測った発話境界の誤差ではなく、p50／p95／最大誤差は引き続き未測定です。
