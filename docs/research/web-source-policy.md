# URL取り込みの対象と記事抽出の調査

確認日：2026-11-01。以下はローカルPCで利用者が指定した作品を取得して読む機能の判断であり、作品の再配布許諾ではない。取得ツールのライセンスと、掲載サイトの条件・本文の著作権を分けて扱う。

## noteの先行実装

先行ツールのコードとライセンスを確認した。ツール自体のインストール・実行や一括取得は行っていない。Ripolaでは同じブラウザ向けJSONエンドポイントを、指定された1記事の取得に使う。

| 実装 | ライセンス | 方式・Ripolaへの適合 |
| --- | --- | --- |
| [laiso/unnote](https://github.com/laiso/unnote) | [MIT](https://github.com/laiso/unnote/blob/master/LICENSE) | JS製。ブラウザ向けの非公式JSONエンドポイントで著者の記事一覧と記事データを取得し、独自JSONを出力する。現行READMEは、自分の記事には公式エクスポートがあることも案内している。著者単位の一括出力CLIをそのまま組み込む必要はない。 |
| [yut0takagi/note-crawler](https://github.com/yut0takagi/note-crawler) | [MIT](https://github.com/yut0takagi/note-crawler/blob/main/LICENSE) | Python製。非公式JSONエンドポイント、ページ送り、間隔制御、JSON/Markdown出力。有料記事はプレビューしか取得できない。HTML本文とメタデータの分離は参考になるが、利用者指定の1記事の読書に著者全件の巡回やPython環境は不要。 |

## noteの実装とブログ記事への拡張

既存のURL欄から、取得元の判定、サイトに応じた取得、共通の記事抽出、既存の本文処理へつなぐ。記事ごとに専用入力画面を増やす必要はない。

- 取得許可の判断と本文抽出を分離する。Readabilityで読めることは、そのサイトの自動取得の許可を意味しない。
- noteは作品の章を列挙するアダプターではなく、1記事を処理するアダプターにする。著者ページの巡回や非公式API全体の取り込みは不要。
- noteは既に本文HTMLを分離して取得できるため、今回ReadabilityやDOM実装の依存物は追加していない。`reader/article-import.ts`が、選択済みの記事HTMLを共通の文書形式へ変換する。汎用ブログのページ全体から本文を選ぶ段階では、Readability等を別に検討する。
- Readabilityを使う場合も本文を文字列へ平坦化せず、段落・見出し・ルビを既存の文書形式へ変換する。脚注・コード・表・画像の扱いと本文欠落を先に検証する。
- 元記事のURL・タイトル・著者を残す。有料・会員限定・年齢制限等の境界を確認できなければ、プレビューを全文として保存しない。認証情報や回避処理は扱わない。
- 任意ホストへのネットワーク取得を許す段階では、ループバック・内部IP・リダイレクト先の検査等が別途必要。現状は対応サイトの公式URLだけを許可し、汎用プロキシは作らない。

自分のnote記事をまとめて扱う用途には[公式エクスポート](https://www.help-note.com/hc/ja/articles/16143464838681)もある。Ripolaの単一記事取得で使うJSONエンドポイントは非公式であり、変更・停止や未知のアクセス状態では取得を止める。取得ツールのMITは本文の再配布許諾を意味しない。
